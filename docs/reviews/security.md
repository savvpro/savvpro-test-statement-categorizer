# Security review — 2026-10-26 — security-reviewer (Sonnet 5.5)
Scope: backend/app (core/security.py, ingest/, services/export.py, api/), frontend/next.config.ts, frontend/src (XSS), Dockerfiles, docker-compose*.yml, .github/workflows | Method: read code against docs/plan/05-security.md; ran `pytest tests/security -q` (pass); ran abuse inputs against `parse_statement` (2M nested SGML tags, 5-figure unclosed STMTTRN, 100k-deep XML, DOCTYPE/ENTITY, 400 kB CSV field x10, 20k-row CSV, `../../etc/passwd.csv`, formula descriptions) and `csv_escape` (leading NBSP/space/newline/VT + trigger chars); probed an unhandled 500 via TestClient.

Verified OK (no finding): upload size is enforced by Content-Length and by counting streamed bytes; defusedxml plus a DTD/ENTITY pre-check; OFX depth capped at 32 and tokens at 500k (all abuse inputs returned 422 in under 1 s; 20k rows parse in 2.5 s); filename is basename-only and the download stem is whitelisted; `csv.writer` is used with `csv_escape` on every user-derived cell; the LIKE search escapes `%` and `_`; no `dangerouslySetInnerHTML` in frontend/src and `react/no-danger` is an error; CORS is an allowlist with no credentials; request-id regex is enforced; `/docs` and `/openapi.json` are off when `APP_ENV=production`; both images run non-root; API containers are read-only with cap_drop ALL; lockfile, audit and dependabot coverage is present.

| ID | Severity | Location | Finding | Recommendation | Status |
|---|---|---|---|---|---|
| SEC-1 | Med | docker-compose.yml:`web.ports` ("3000:3000"); docker-compose.prod.yml:`web.ports` | The web port binds 0.0.0.0. The app has no auth, and the proxied API includes `DELETE /api/v1/statements/{id}`, `PATCH /transactions/{id}` and `export.csv`. Anyone on the LAN can read, export or purge the financial data. Plan 05 §2 says to bind to localhost or the compose network. | Publish as `"127.0.0.1:3000:3000"` in both files. Document how to put an authenticating reverse proxy in front for any other exposure. | open |
| SEC-2 | Low | .github/workflows/release.yml:6-8 (top-level `permissions`) | The workflow-level `contents: write` and `packages: write` are inherited by the reusable `ci` job (`uses: ./.github/workflows/ci.yml`) and by the checkout steps. Plan 05 §8 allows `packages: write` only in the release job. | Set the top-level block to `contents: read`. Keep `packages: write` on `images` and `contents: write` on `release`, which already declare their own. | open |
| SEC-3 | Low | backend/app/main.py:288-289 with the `Exception` handler at core/errors.py:152 | The unhandled-500 response bypasses `SecurityHeadersMiddleware`. The probe showed a 500 carrying only `x-request-id`, `content-length` and `content-type`, with no CSP, nosniff, X-Frame-Options or other headers. | Install the `@app.exception_handler(Exception)` response through a wrapper that adds the headers, or add the headers inside `problem_response`. | open |
| SEC-4 | Low | backend/app/core/ratelimit.py:12 with backend/entrypoint.sh:6 | The limiter keys on `get_remote_address`. Behind the Next.js rewrite, uvicorn `--proxy-headers` only trusts 127.0.0.1, so the client IP is always the web container. All users share one 30/min bucket. Spoofing is not possible, but one client can lock out the rest. | Set `--forwarded-allow-ips` to the web container's network (or `FORWARDED_ALLOW_IPS`) so X-Forwarded-For is honored, and key on that. | open |
| SEC-5 | Low | frontend/next.config.ts:10 | `script-src 'self' 'unsafe-inline'` weakens the CSP, so an injected inline script would run. No injection sink was found, so this is defense-in-depth only. | Use nonce-based CSP via Next middleware (`script-src 'self' 'nonce-…' 'strict-dynamic'`), or document this as an accepted trade-off in SECURITY.md. | open |
| SEC-6 | Low | docker-compose.yml:`web`; docker-compose.prod.yml:`web` | The web service lacks the hardening applied to `api`: no `read_only`, `cap_drop: [ALL]`, `no-new-privileges`, or tmpfs. | Copy the api service's `read_only: true`, `tmpfs: [/tmp, /app/.next/cache]`, `cap_drop` and `security_opt` blocks. Verify the Next standalone server still starts. | open |
| SEC-7 | Low | backend/app/core/config.py:12 (`env: str = "development"`) | The default environment is development. A container started without `APP_ENV` exposes `/docs` and `/openapi.json` with relaxed CSP. docker-compose.yml (non-prod) does not set `APP_ENV`. | Default to `production`, or set `APP_ENV: production` in the Dockerfile. Dev and tests opt in explicitly. | open |
| SEC-8 | Low | .github/workflows/security.yml:44 | `uvx pip-audit` is unpinned, so a new release could change the gate or the supply-chain trust. | Pin it (`uvx pip-audit==<ver>`), or add pip-audit to the locked dev group and run it via `uv run`. | open |
